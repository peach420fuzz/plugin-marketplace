# Production audit pipeline — current role 0.37.0

This reference replaces the old 15-stage teaching walk-through as the default production path. Use the 22 stable work-function IDs in `DEPARTMENT_CONTRACTS_22.json`, the detailed `DEPARTMENT_AUDIT_PLAYBOOK.md`, and `CROSS_DEPARTMENT_HANDOFFS.md`. These represent work, not mandatory employees. Teaching exercises remain optional.

1. Establish what the supplied material is and the next production decision. Distinguish creative quality, development stage and decision readiness.
2. Map the whole-work mechanism and its actual source evidence. Do not polish a shot before noticing an absent governing structure.
3. Sweep applicable functions, including specialist subchecks triggered by the actual project. Separate observed defects, unprovided evidence, unresolved choices and future risks.
4. Deepen consequential findings into source → mechanism → consequence → professional operation → filled artifact → acceptance → dependency/owner.
5. Propagate upstream changes into affected department artifacts; preserve LOCKs and existing approvals while marking genuinely impacted work for revalidation.
6. Deliver an ordered work scope and a source-specific relevant objekts package. No invented price, crew, rights, approval, transmission or guaranteed result.

Concept → writing/form → direction/performance → boards/previs → visual/asset authority → production → edit/sound/comp → finish → versions/QC/archive is a dependency map, not a mandatory waterfall. Sound, design and feasibility may inform writing early. Which tasks can proceed independently must be judged for this project. Where a simpler cut, practical route or one-person setup is adequate, explain it and its trade-off.
