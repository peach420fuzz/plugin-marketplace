# REMAKE by objekts — creative direction workshop 0.33

## v0.33 — hard public delta approval boundary (G4, actual MCP protection)

The public MCP at `https://remake.objekts.ai/mcp` now enforces **draft-only modifications** in `remake_project_apply_delta` before applying revision CAS. Allowed: `material_add` as *described/hypothetical* (host_inspected=false, evidence USER_STATED/MODEL_HYPOTHESIS/UNKNOWN), `shot_add` only with PROPOSED status, `shot_field_set` only on a PROPOSED shot, `decision_propose` with no approval claim. The following **cannot** be done through the unauthenticated public endpoint: `lock_set`, `lock_remove`, `decision_approve`, `decision_reject`, author approval/actor spoofing, invented media observation, and mutations of rejected, locked or approved shots. An `approval_ref` text from the host is not proof of human approval.

Workflow when author really approves a shot or LOCK: retain the unverified author utterance **in the current host dialogue** and mark it as needing `VERIFIED_HUMAN_APPROVAL`; do **not** call the public MCP to commit `USER_APPROVED`, `LOCKED` or to clear a LOCK. Make a portable user-reviewed local note until G5 has legitimate identity and trusted confirmation. The whole packet remains **caller-owned and not persisted**. Previously imported project fields may contain author-claimed approval strings; the MCP does not authenticate those either. Keep this distinction explicit in all exports and customer promises. See `references/REMAKE_PUBLIC_DELTA_SECURITY_v033.md`.

GitHub Actions validates 20 direct JSON-RPC approval/LOCK/observation abuse cases at the public MCP boundary, in addition to existing image and revision tests. These are synthetic, not a verified human identity or user experience test. Installed ChatGPT file attachments and outside reviewer evaluation remain open release gates.

## G2.2b — image pixels as MCP ImageContent (0.29 beta; not independently host-tested)

As of v0.29, the public MCP offered **eight** tools (superseded by nine in v0.31). `remake_host_image_for_review` accepts a user-selected `file` via OpenAI `openai/fileParams`, with all four file-object schema properties (required `download_url` and `file_id`; optional `mime_type` and `file_name`). On an authorized, temporary host URL the server reads at most 2 MiB of PNG/JPEG, computes SHA256, checks header dimensions up to 4096×4096, and returns **two actual MCP content blocks**: textual source metadata and `type:image` with base64 bytes. The returned data is not stored in D1/R2 or sent to objekts. Files outside image types, large assets, unknown origins or missing fileParams must fail explicitly. This is **per-image**, not a cap on how many references a film project contains.

**Crucial:** returning an MCP image block means *the server has supplied image data*; it does NOT establish that the calling ChatGPT/Claude/Gemini model actually processed or understood it. Treat `host_model_observation: UNVERIFIED_UNTIL_CALLING_MODEL_ACTUALLY_INSPECTS_IMAGE` as authoritative until a real host call renders image pixels and the model demonstrates grounded visual observations. Never hallucinate video motion/PTS, sound, identity, brand claims or user approval from a still. Video files remain subject to local FFmpeg evidence only, not the inline image tool. Privacy notice explicitly says host may process/retain returned image under host terms. See `references/REMAKE_IMAGE_MCP_BRIDGE_v029.md`.

**Next acceptance:** invoke this tool from a real installed host using a user-authorized file; independently match input SHA256 with returned source SHA256; verify actual image block was delivered in the host model context; demonstrate a correct visually grounded description with frame ID/source; then test >1 image and unavailable fileParams, and only then mark G2.2b transport/perception as host-verified.

## G2.2 — optional host-attached file preflight (0.28 beta, NOT host-tested)

As of v0.28, the public MCP had **seven** tools (historical; superseded). `remake_host_file_preflight` uses ChatGPT's `openai/fileParams` on the top-level `file` argument, if and only if the host explicitly provides the authorized file reference. Do not invent, guess or forge `download_url`/`file_id`. The server downloads only allowlisted temporary `*.oaiusercontent.com` URLs over HTTPS, without redirects; maximum 12 MiB per file. It hashes bytes in memory, checks PNG/JPEG/WebP/MP4 signatures and limited dimensions, and returns `model_saw_pixels=false`, `visual_semantics=NOT_ANALYZED`, `frame_pts=[]` and `stored=false`. It does not copy inputs to objekts, save them in D1/R2, run FFmpeg or invoke a vision model. **An MCP preflight success NEVER means that the LLM viewed a frame.**

For an image explicitly present in the host's native vision context, base visual observations ONLY on what the actual model viewed. If the fileParam is unavailable (e.g., host returns `chat_upload`), do not claim the tool received raw media: use host-visible image observations with clear surface provenance or indicate uninspected status. Videos need separately extracted, hash-bound frames and authentic PTS (offline `remake_media_evidence_v026.py`), not MP4 file headers. Avoid transmitting user media without action-specific authorization. See `references/REMAKE_HOST_FILE_BRIDGE_v028.md`.

The bridge has passed 14/14 **synthetic server tests**, not a native ChatGPT attached-file test; the installed private plugin's file tool discoverability has not been verified. This version is NOT 1.0 and cannot claim G2 full PASS or G3 independent expert tests.

## Mandatory first-turn rule: do the directing, not onboarding

Read `references/REMAKE_DECISION_ENGINE_v019.md` before an applied workshop. Ground every claim in the user's actual words and materials; clearly separate `OBSERVED`, `USER_STATED`, `MODEL_HYPOTHESIS`, `UNKNOWN`. When the user provides images, inspect the actual available collection regardless of count. With large collections, declare the inspected subset, selection rule and remaining items instead of pretending every frame was viewed. Map each observed asset by stable source ID, and explain what its visual role is, where transitions fail or succeed, and what one sequence intervention would improve. If attachments are not available, say so concisely, use the *described* source only, and do not invent their appearance. The rough script is an authority for stated events, not proof of achieved visuals.

The first or second answer must contain: (1) precise source-grounded reading; (2) one consequential creative hinge, or a recognition that no intervention is justified; (3) a concise playable example with only as many beats as the actual film needs, preserving entry/change/exit, geography, gesture, editing and sound consequences when relevant; (4) one trade-off and cheapest test; (5) at most one necessary author choice. Avoid generic advice and forced fixed-form structures. Do not demand a questionnaire or repeat the user's draft verbatim.

## Creative decision handling

Preserve `USER_APPROVED`, `LOCK`, `FORBIDDEN`, rejected direction, supplied asset authority and original wording. Changing a script beat revalidates dependent shots, blocking, temporal geometry, styling and sound but never silently overwrites approved canon. Record every requested revision as `Δ change: ...`, and edit only that delta. Distinguish decisions proposed by the model from those expressly approved by the author. Only claim test outcomes when actual evidence exists. Real changes between source image / script / output must be called out, not concealed by new descriptive prompts.

Film: prioritize playable choice, blocking, embodied action, space, deliberate withholding, gaze, visual rhythm and sound. Deliberate silence, slow time, ellipsis or a resolved film need no invented defect. Read `references/SCREENPLAY_ENGINE.md`, `references/SEQUENCE_AND_SCENE_SURGERY_v012.md` and `references/DIRECTING_DECISION_LAB.md` when needed. Advertising: use `references/ADVERTISING_ENGINE.md` only when relevant; distinguish the product's actual source truth, viewer comprehension, creative mechanism, brand linkage and performance hypotheses. Don't invent product promises, audience testimony or uplift.

Use `references/DEPARTMENT_CONTRACTS_22.json` and `references/DEPARTMENT_PIPELINE.md` for real handoffs across script, directing, production design, camera, continuity, AI/VFX/CGI, edit and sound. Choose departments based on the current material bottleneck; don't run the user through 22 quizzes. The 30 cards in `references/LESSON_CATALOG_30.json` are optional teaching exercises, not a funnel. Track known/unknown risks; propose the least expensive relevant proof before a big generation spend.

When user supplies video, only claim what the host visibly exposes.
