# SKRIPT — source-qualified craft consumer v1

**Draft, not released.** The existing SKRIPT Skill can write film, series, advertising, music-video and animation scripts without any private Atlas. A link does not grant access to private role100 research. Apply craft context only when the current authorized host has actually supplied `objekts.craft-context/1`.

1. Understand the author-approved scenario, formal question, scene causality, time, action, objects, character knowledge, chosen final and all LOCKs.
2. In authorized local/Work mode use `tools/craft_bridge.mjs` on the explicit studio checkout with `consumer:"skript"`, `mode:"general"`, `prompt_family_ids:["PF-011"]`. If unavailable, continue with normal source-backed SKRIPT engines and mark Atlas not consulted.
3. Check each selected research KN-ID, source and limitations before proposing a craft mechanism. Connect C02 beats, C14/C15 action/space, C25/C27 POV/perspective, C43/C47 audio, C49/C50 cuts/duration only when pertinent.
4. Write performable actions and relationships, not a list of technical effects. For advertising check real product facts, causal hook, legibility and timed 6/15/30/60s variants only where requested; do not invent measured ad performance.
5. In a private decision ledger distinguish candidates considered, actually used, rejected, unverified and owner-approved. An unobserved video is not proof of successful form. A source extraction is not an adopted studio rule.
6. Preserve selected ending, identity, wardrobe, prop state and source roles. Change only requested delta; avoid reintroducing rejected concepts.

No automatic sharing with REMAKE/Production Desk, and no unauthorized transfer of confidential packets to a public server.

## Verifiable SKRIPT decision ledger

When an authorized local source supplies the packet, check `query_coverage.curated_problem_matches` before deciding how a scene should be staged or cut. The original S10 index has 46 author-curated provisional problem→KN routes; it is navigation, not a default screenplay. Read `craft_candidates` and choose only cases with a direct causal use. `downstream_research_options` are secondary, not selected or approved.

Record the actual authored scene revision via `tools/craft_consumer_verified.mjs` with `consumer:"skript"`, exact `artifact_id`, identical `immutable_locks`/`reference_roles`, and one evidence-linked entry per actually used KN-ID. Allowed effect types include `scene_structure`, `action`, `sound_design`, `montage`, `image_language`, `ad_hook`, `animation`. Each has an exact scene locator, performable change, causal explanation, counterexample check and a proposed viewer/edit/rehearsal test. The receipt is not a substitute for the script, nor proof that any source film was watched or final audience response measured.

This is a **local, permissioned** protocol; the public portable Skill does not remotely fetch the private role100 GitHub repository, execute tests, create films or send the user's brief to REMAKE.


**Production verification boundary:** A caller-provided Craft Context packet or a claimed SHA256 is not sufficient provenance. The verified OPS wrapper must reload the authorized local `atlasDir` and regenerate source candidate membership, source URLs, LOCKs, family routes and corpus digest before it can issue a source-use receipt. A public plugin has no such local private checkout and therefore must not claim verified Atlas usage.
