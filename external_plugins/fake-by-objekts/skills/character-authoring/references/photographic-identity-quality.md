# FAKE — photographic identity quality contract

Applies to reference-guided native generation and human review, not hard spatial conditioning. GNM parameters control the mesh deterministically. Native image generation interprets visual references probabilistically. Never claim an enforced vertex match, a hidden ControlNet, a fixed seed, guaranteed output count or automatic result retrieval without verified host support.

## 1. Freeze the evidence before a request

Record the observed project/state revision, approved Master if any, requested delta, active LOCKs and reference roles. Keep project credentials and private URLs inside the app. Preserve separate roles:

- Character State: authored anatomy, appearance and capture authority.
- Real GNM mesh: measurable geometric authority.
- Approved photograph: visual identity authority after explicit approval.
- Source portrait: separate likeness evidence when available and authorized.
- Scene, garment and style references: their named scope only.

Resolve conflicts explicitly. A newly authored nose delta does not retroactively change an old Master. A style image does not replace identity. Missing attachments are unavailable evidence, not imaginary references.

Current widget exports a multiview geometry board. A single target-pose reference is a proposed runtime improvement, not a currently available action. When the app can export it, use the same intended projection, head angle and framing as the requested photograph. Supporting orthographic views aid anatomical comparison; depth/normal images are not native spatial conditioning merely because they were attached.

## 2. Establish Master under readable conditions

Use one neutral audition image before a Cinematic or Fashion treatment. Suggested test design: fully fictional adult subject, eye-level camera, restrained 85 mm full-frame-equivalent perspective, face readable across the focus plane, simple neutral background and one broad motivated key with weaker fill. Focal length and aperture language are visual intentions, not verified capture metadata or controllable host camera settings.

Carry the actual anatomy into one self-contained English prompt. Derive only supported traits from state, visible geometry and the user's brief:

- cranial length/width/height, forehead angle and temporal shape;
- zygoma-to-jaw relation, mandibular angle, chin width/height/projection;
- eye spacing, aperture, canthus tilt and lid forms;
- nasal root, bridge, length, alar width, tip projection/rotation;
- philtrum, mouth width, upper/lower lip form;
- ear size/projection and explicitly authored asymmetry;
- approved skin marks, hairline, hair and facial hair;
- body, hands and wardrobe only when visible, preserving known proportions.

Use relational anatomy rather than pasting PCA coefficients. Do not add invented ratios, units, pigmentation, scars or asymmetries. Unknown traits remain unspecified or require a deliberate user choice.

Describe region-dependent pores, subtle complexion variation, fine vellus hair, eyelid thickness, lip texture, corneal wetness, tear meniscus, restrained catchlights and differentiated hair fibres. The key, fill, exposure and materials must agree. Preserve natural optical acuity and restrained highlight roll-off. Grain does not repair anatomy or smoothed synthetic skin.

State acceptance constraints concretely: preserve the unusual bridge/nose/jaw/eye relationships actually authored; retain signed asymmetry; avoid mannequin material transfer from the geometry reference, global skin smoothing and generic beauty normalization. A negative instruction is a constraint to check, not a guarantee of compliance.

## 3. Keep request and result states separate

Use only observed states: prepared, sent to host, awaiting actual image, actual result available, manually imported, rejected or explicitly approved. A widget follow-up means sent only. A request for four images with one returned file means 1/4 received. A contact sheet is one file, not four independent candidate assets.

If native generation is available, invoke the real host tool using actual attached references. If a reference cannot be included, disclose that specific gap and do not pretend it conditioned the result. If host return/import is unavailable, use the verified manual save/import path. Never switch to a paid API or cloud inference as an implicit fallback.

## 4. Grade each actual image through independent gates

| Gate | PASS evidence | REJECT / uncertain evidence |
|---|---|---|
| Comparable viewpoint | Head angle/crop permit meaningful correspondence | Different angle, occlusion or perspective hides the intended trait |
| Anatomy | Distinctive silhouette and feature relations preserved | Nose shortened, jaw narrowed, eyes enlarged, asymmetry normalized |
| Photographic material | Coherent skin/eye/hair response under one plausible light setup | Waxy skin, CG shading, invented pore pattern, smeared hair roots |
| Identity continuity | Same Master proportions and distinctive marks in jointly visible regions | Different person, altered hairline, missing marks, feature drift |
| Requested delta | Requested scene/wardrobe/light change visible; other attributes stable | Attractive restyling that also changes identity or body |
| Approval | Actual user action approves that imported image and revision | Assistant preference or newest image silently promoted to Master |

Do not average these gates into a beauty score. One severe anatomy or identity failure rejects a candidate regardless of texture. Uncertain evidence remains uncertain. Inspect the full frame and meaningful face/eye/hair crops when image access allows it; never claim unseen 100% detail was inspected.

Automatic landmarks or similarity scores are diagnostic only. Pose registration, visibility and topology mapping must be validated before quantitative comparisons. No invented universal threshold and no face-embedding score used as sole proof.

## 5. Use targeted retry, not identity drift

Keep the authored state frozen when generation fails. Identify the concrete failed feature and request one correction using the actual evidence. Do not modify GNM to match a generator mistake, stack stronger adjectives blindly, or call a later edit the new identity. Preserve rejected outputs as rejected, if the runtime supports records.

For production, begin from the approved Master plus current anatomical authority and the requested delta. A latest variant is not a substitute Master. Explicitly reapprove a changed identity when needed. If no candidate passes, report that result; do not manufacture readiness.

## 6. Controlled experiment before precision claims

Test four substantially different fictional adult identities under matched neutral capture intentions: text only; same brief with target-pose GNM when implemented; GNM plus one supporting view when supported; then approved Master plus GNM for a changed camera/scene. Record actual attempts, returned files, accepted candidates, precise failure reasons, observed host and latency. Note stochastic variation when seed/model pinning is unavailable.

Do not publish precision 3D-to-photo claims until reference-guided trials improve geometry fidelity over text-only while retaining photographic quality, and subsequent images preserve Master identity. This package defines the experiment; it does not claim the trials ran.
